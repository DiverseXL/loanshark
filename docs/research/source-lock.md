## Mismatches and discarded material

- A pasted third-party summary said a web app can have the wallet register the ML-DSA key and sign `MsgRegisterPQCKey`. It cites no primary source and contradicts claim 10. Discarded.
- Claim 38 and claim 39 do not contradict each other but describe different surfaces: the published adapter implements the Cosmos-lane sending flow only, while the injected wallet object carries the wider native API recorded at runtime. Where the two differ, the runtime wins for what `window.qorex.native` exposes, because that is the object the page actually calls. The adapter is a narrower consumer of it.
- Claim 43 is a documented gap, not a disagreement: neither the source nor the runtime record offers a native chain-id getter, so the app must infer the chain from `enable` rather than read it. If a getter is later confirmed, the guard should use it instead and this claim should be updated.
